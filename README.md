# HigherWorld

HigherWorld 是面向 Minecraft 1.21.11 / Fabric 的稀疏立方区块运行层。它保留原版
维度类型和已有 `.mca` 存档，不再把维度的 `min_y/height` 当成可放置方块、移动、
保存或渲染的硬边界；边界之外的数据按独立的 `16 x 16 x 16` cube 按需加载。

## 当前实现

- cube 坐标使用三个 32 位整数，不把 Y 压回二维区块键，也不分配整根高度数组。
- 每个 region 包含 `16 x 16 x 16` 个 cube 槽位。
- region 是带 CRC32 校验的追加日志；进程在记录中途退出时，之前的数据仍可读取。
- cube 记录保存 block/biome palette、生成器版本和方块实体 NBT；旧 HWC2 记录可向后兼容读取，
  脏 cube 会定期、离开视距及关服时保存。
- 服务端按玩家位置维护三维 cube 视距，客户端接收加载、卸载和方块更新包。
- 客户端渲染节数组改成以相机为中心的三维环，原版高度之外也能重建网格。
- 方块访问、流体、碰撞、邻居更新、随机刻、方块实体刻、高度查询和基础光照均会路由到 cube。
- 原版 BlockPos 网络字段在超出 12 位 Y 时使用转义编码，因此客户端和服务端都必须安装本模组。
- 原版 `.mca` 继续负责原版高度带内的数据与实体兼容；外部方块由 `.hwr` 文件负责。

cube 文件位于：

```text
<world>/cubic_chunks/<dimension namespace>/<dimension path>/region3d/r.<x>.<y>.<z>.hwr
```

## 高度语义

“无限高度”采用 Cubic Chunks 的稀疏语义：世界不会预先分配从底到顶的数组，也没有
维度配置规定的建造顶/底面，只为实际访问和玩家视距内的 cube 付出内存与磁盘成本。
坐标本身仍受 Java/Minecraft 整数坐标约束；当前原版渲染和实体分节长键可稳定覆盖约
`Y = -8,388,608..8,388,607`，存储及扩展方块网络包使用完整有符号 32 位 Y。

创建世界时可在“世界类型”中选择“无限向下”；该类型会在原版世界底部以下按需生成
连续的深板岩与洞穴。该世界的原版噪声生成器会直接使用不含基岩地板的地表规则，
不会在区块加载后替换任何基岩方块；同时原版高度带与下方 cube 共用移除底部渐变后的密度场，
因此地形会跨过 `Y=-64` 连续生成。下方洞穴复用原版
`minecraft:caves` 的 base-3D density 路由，在其未受顶部/底部渐变影响的范围内采样，
再通过带间交叉淡化与种子坐标偏移无限延伸；不会把 Overworld 的大陆与地表高度场投影到地下。
噪声含水层以及逐 cube 无法安全生成的地下湖泊、流体泉会被禁用，因此洞穴不会在
`Y=-64` 以下形成浮空岩浆层。依赖跨 cube 支撑的植被装饰同样不会在扩展区生成；
矿石、紫晶洞和滴水石等可局部生成的地下特征仍会保留。
此设置只影响新生成的区块；已经写入存档的原版区块不会被自动改写。
创建世界时也可选择“自定义世界”，通过原版“自定义”按钮选择地下生成深度（128、256、512、1024
格或无限）；选择会保存到该世界的 `cubic_chunks/custom_world_settings.json`。
其他世界类型在原版高度带之外的新 cube
仍默认是空气，供建造、命令或其他生成器写入。天空光在稀疏列上按最高非空气方块计算，
发光方块提供自身亮度；完整跨 cube 光传播仍沿用后续可替换的光照接口。

实现结构参考了 1.12.2 Forge 的第一代 Cubic Chunks（稀疏 CubeMap、三维玩家视距、
BlockPos 包转义）以及 CubicChunks3 的现代缓存/渲染设计，但运行代码保持 Fabric
1.21.11/Yarn API。

## 构建

```powershell
.\gradlew.bat build
```
