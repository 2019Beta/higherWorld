# 区块加载优化记录

本轮在工作区已有改动上继续优化，没有更改生成参数、视距或每帧预算。

## 改动

- `TerrainInterpolation`：同一 Z 插值单元内复用 X/Y 插值结果，保持浮点运算顺序；Z 采样间距为 1 时使用连续写入路径，避免循环重排造成退化。
- `OpenClTerrainAccelerator`：分别缓存表面采样、批量密度采样、单块及批量栅格化内核的参数。缓冲区对象固定，坐标和密度数据仍照常更新。连续同参数的自定义批次省去 35 次 `clSetKernelArg` 调用；批量大小、种子、网格或插值模式变化时重新绑定。缓存受原有队列锁保护，绑定失败时不保留有效缓存。
- `ClientCubeCache`：新增区块只增量更新 256 个柱顶；替换和卸载仅在原最高点下降时扫描对应柱。取消替换时先移除再添加导致的两次整列扫描；空区块跳过 4096 个方块的高度检查。
- 渲染失效集合改为保留插入顺序的去重集合，保留每 tick 的 192 个重建预算，避免持续流入时哈希遍历顺序让旧请求长期等待。

## CPU 微基准

运行环境：本机 JDK 21.0.2。比较优化前的逐体素算法（同样使用预计算坐标表）和当前算法；32 组固定种子输入，分别预热 10,000 次，4 轮交替顺序测量，每轮 20,000 个区块，取最短耗时。

| X/Y/Z 采样间距 | 原实现 ns/区块 | 优化后 ns/区块 | 速度比 |
| --- | ---: | ---: | ---: |
| 1/1/1 | 7346.4 | 7517.6 | 0.98 |
| 2/2/2 | 7355.4 | 7044.2 | 1.04 |
| 4/4/4 | 7319.8 | 4439.5 | 1.65 |
| 8/8/8 | 7323.7 | 2929.8 | 2.50 |
| 16/16/16 | 7322.7 | 2123.3 | 3.45 |

这些数据只反映 CPU 密度栅格化，不代表噪声采样、整个区块生成或实际世界加载的加速倍数。默认采样间距是 4/8/4，表内并未单独测量该配置。

正确性检查覆盖 125 种 X/Y/Z 间距组合，每种包含随机密度和 8 种零值、极值、非有限值输入，共 1,125 个网格，逐体素结果均与原实现一致。

从项目根目录复现独立检查与基准：

```powershell
javac -d build/raster-benchmark src/main/java/org/devt/higherworld/world/TerrainInterpolation.java src/test/java/org/devt/higherworld/world/TerrainRasterBenchmark.java
java -cp build/raster-benchmark org.devt.higherworld.world.TerrainRasterBenchmark
```
